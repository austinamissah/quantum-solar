# Source: `co_residential_{season}_{daytype}.csv`

Representative Colorado residential household load, 24 hourly kWh per dwelling,
bucketed by **(season, day type)**:

| file | season | day type |
| --- | --- | --- |
| `co_residential_summer_weekday.csv` | summer (Jun–Sep) | weekday |
| `co_residential_summer_weekend.csv` | summer (Jun–Sep) | weekend |
| `co_residential_winter_weekday.csv` | winter (Oct–May) | weekday |
| `co_residential_winter_weekend.csv` | winter (Oct–May) | weekend |

- **Dataset:** NREL *End-Use Load Profiles for the U.S. Building Stock* (ResStock),
  release `resstock_amy2018_release_2` (2024). OEDI submission 4520.
- **Source file (state aggregate, single-family detached, baseline upgrade 0):**
  `https://oedi-data-lake.s3.amazonaws.com/nrel-pds-building-stock/end-use-load-profiles-for-us-building-stock/2024/resstock_amy2018_release_2/timeseries_aggregates/by_state/upgrade=0/state=CO/up00-co-single-family_detached.csv`
- **Dataset landing page:** https://data.openei.org/submissions/4520
- **Documentation:** https://www.nlr.gov/buildings/end-use-load-profiles
- **Regenerated by:** `scripts/make_resstock_profiles.py` (committed; re-download +
  re-derive all four CSVs).

## How these profiles are derived

The aggregate CSV is a 15-minute, year-long (AMY 2018) sum of electricity across
all represented Colorado single-family-detached dwellings. For each 15-minute row
we:

1. computed per-dwelling load =
   `out.electricity.total.energy_consumption.kwh / units_represented`
   (`units_represented` ≈ 1.49M CO single-family detached homes),
2. shifted the **interval-ending** timestamp back 15 min to its interval-start
   local hour (so 00:15–01:00 → hour 0),
3. assigned each row to a **season** (summer = Jun–Sep, winter = Oct–May) and a
   **day type** (weekday/weekend) from its real 2018 calendar date,
4. summed the four 15-minute intervals into hourly kWh, then averaged over every
   matching day in the bucket.

**Season boundary** is pinned to the Xcel RE-TOU tariff's own summer/winter split
(summer Jun–Sep carries the higher on-peak rate), so the load season and the URDB
price season never disagree. **Day type** uses the 2018 calendar — the same
AMY-2018 year the annual loop classifies days under
(`quantum_solar.data.calendar`). **Holidays** are billed as weekdays: URDB carries
no holiday schedule and the ResStock weekday aggregate folds holidays into
weekdays (a known v1 limitation).

Result (per-dwelling daily totals): summer ≈ 28 kWh, winter ≈ 31 kWh, with the
expected residential diurnal shape (overnight low, evening peak ~1.6–1.9 kWh).
Winter runs higher (electric heating fans, longer lighting hours) and weekends
slightly above weekdays (more time at home).

> **Note:** these supersede the earlier July-only summer-weekday profile. The
> summer bucket now averages all Jun–Sep weekdays, consistent with the tariff
> summer season, so its values differ slightly from the previous file.

Regenerating requires re-downloading the ~45 MB aggregate CSV; the derived
24-value profiles are committed here so no network is needed at runtime.
